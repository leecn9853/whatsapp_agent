# 支付宝匹配数据表生成技能

## 核心流程

这不是通用 Excel 处理任务——数据来源（固定的一个接口）、聚合规则都已经写死在工具内部，
不需要先用 `inspect_excel` 看结构，也不需要自己判断分组维度或聚合方式。用 `execute` 工具
跑本技能自带的 CLI 脚本即可：它会自己分页拉完当天全部支付宝匹配流水、按数据类别/明细分类/
金额区间三级动态聚合、现场用代码拼出一份 Excel，最终会把这张 sheet 截图成一张带报表ID
水印的 PNG 图片。**不会**生成或发送 Excel 文件——Excel 本身只落进内部快照供追溯。

## 怎么调用

```
python3 /workspace/skills/alipay-report/scripts/generate.py \
  --report-id=<report_id> --caller=<caller> --user-id=<user_id>
```

- `--report-id`：必填，用当前对话上下文里的 report_id（系统提示里的"当前任务 report_id"）。
- `--caller`/`--user-id`：可选，用当前对话上下文里的 caller/user_id（系统提示里能看到），
  没有就不传。
- 不需要任何其他参数——数据来源、聚合规则都是固定的，一次调用即完成拉取、聚合、出表、
  截图全流程，不需要多次调用做数据聚合。

**输出契约**：`execute` 返回后看最后一行 stdout：
- `RESULT_PATH:<路径>` → 把该路径原样传给 `save_file` 工具的 `source_path` 参数，图片就会
  发给用户，不需要额外传 `filename`/`content`。**不要**再用 `read_file` 去预览这个路径——
  图片已经通过 `save_file` 发给用户了，预览没有必要。
- `ERROR:<说明>` → 把说明转述给用户，不要猜测原因、不要重试。

## 报表结构（方便转述给用户）

- 表头列（从左到右）：序号/数据类别/明细分类/金额区间/下单笔数/成功笔数/下单金额/成功金额/
  成功率/备注。
- 标题行日期取自接口返回的当日日期字段，不是固定日期。
- 数据类别 → 明细分类两级分组，取值集合与出现顺序完全由第三方接口当次返回的数据决定——
  不要凭经验假设应该有哪些类别，每次都以实际拉到的数据为准。
- 每个明细分类下按 5 个固定金额区间（0-500/501-2000/2001-10000/10001-30000/30001以上）
  各出一行；某区间当次没有记录就跳过，不显示零值行。
- 明细分类结束后有一行「小计」；数据类别结束后有一行「合计」（该类别下所有小计简单相加）。
- 成功率 = 成功笔数 / 下单笔数（按笔数算，不是按金额）。
- 序号列贯穿全表连续编号。

## 关于失败情况

如果第三方数据服务没启动，或者当次没有返回任何记录，脚本 stdout 最后一行会是
`ERROR:<中文说明>`——直接把这段说明转述给用户即可，不要自己猜测原因或编造数据。

## 不需要做的事

- 不需要改 third_app——接口字段已经齐全，金额区间/成功率/序号本就该由这个脚本计算。
- 不需要维护或假设一份固定的"数据类别/明细分类"清单——完全动态，接口以后返回新类别
  也不用同步改任何配置。
- 不需要多次调用做聚合——一次调用即完成拉取、聚合、出表、交付全流程。
