# 散点图（`chart_type: "scatter"`）

## 适用场景

- 观察两个**数值变量**之间的相关性/分布关系，比如"广告投入 vs 销售额""价格 vs
  销量""员工工时 vs 产出"。
- 用户关心的是"这两个指标有没有关系、关系是正向/反向/无关"，而不是类别对比或
  随时间的趋势——那两种场景分别用 [bar-chart.md](bar-chart.md) 和
  [line-chart.md](line-chart.md)。

## 数据要求（重要，容易踩坑）

散点图的参数语义和其他三种图表**不一样**，必须特别注意：

- `category_column` 在散点图里**不是类别标签列，而是 X 轴的数值变量**（工具实现
  上把它当作横坐标的数值取值，直接用来定位每个点的 X 坐标，不是当作分类分组）。
  不要把它填成"部门""产品线"这类分类列名——那样画出来的散点在 X 轴上没有数值
  意义，图表会不可读。
- `value_columns` 是 Y 轴的数值变量，可以传多个：每传一个列就会生成一个独立的
  系列（一组点），和同一个 X 变量配对，适合同时看"X 分别和 Y1、Y2 的关系"。
- 两个轴对应的列都必须是数值列，且理论上都应该是连续变量（不是分类、不是
  时间字符串）。

## 通常不需要先聚合

- 和折线图/柱状图相反，散点图的价值恰恰在于展示**每个原始观测点**的分布，聚合
  求和/求均值会抹掉个体差异、让相关性看不出来。
- 除非原始数据量特别大（几千行以上导致图表卡顿或点挤成一片），一般应直接对
  明细数据画散点图，跳过核心流程里"判断是否需要先聚合"这一步。
- 如果确实数据量过大想降噪，可以按某个自然分组做聚合（比如按天取均值），但要
  在回复里跟用户说明这是聚合后的关系，不是逐笔明细。

## 参数示例

假设已有一张明细表「广告投放明细」，表头为 `投放金额 / 当日销售额`，两列都是
数值：

```
create_chart_sheet(
    filename=<上一步返回的文件名>,
    sheet_name="广告投放明细",
    chart_type="scatter",
    category_column="投放金额",
    value_columns=["当日销售额"],
    title="广告投放金额与当日销售额的相关性",
    new_sheet_name="投放销售相关性图",
)
```

## 常见错误

- 把 `category_column` 填成分类列（如"部门""产品线"）——散点图两个轴都应该是
  数值变量，分类列没有数值坐标意义。
- 只有一个数值列可用，硬凑一个不相关的列当 Y 轴——至少需要两个有实际关联意义
  的数值列才值得画散点图；只有一个数值维度时应该换用柱状图或折线图。
- 沿用核心流程里"先聚合"的默认动作，把明细数据聚合成汇总表后再画散点——会丢失
  个体分布信息，通常是不必要的。

## 检查清单

- [ ] `category_column` 和 `value_columns` 都是数值列，且两者之间存在业务上想
      验证的关联关系
- [ ] 没有为了套用"先聚合"的默认流程而误聚合掉明细数据
- [ ] 标题说明了在验证哪两个变量之间的关系
